# Conflict count — evidence file for council kill criterion 1

**Question (council, 2026-09-06):** how many times in this repository's history did two rules at different authority levels actually collide such that plain conjunction ("every rule must hold") gave the wrong answer? Threshold: fewer than 3 means the precedence engine is machinery for an absent problem.

**Method:** `rg` over `.claude/rules/*.md`, `.claude/CLAUDE.md`, `JOURNAL.md`, archived specs and tasks for explicit precedence language (`overrides`, `supersedes`, `wins where they differ`, `takes precedence`, `never overrides`, `exception to`); `git log -p` over rule files for rewrites forced by a collision. Counted only cases where both rules could not hold at once, so conjunction was impossible or wrong. Recorded 2026-09-06 at revision `f4c5f7c` plus the uncommitted research folder.

## Result

- **Collisions where conjunction was impossible: 3** (rows 1–3). Pre-emptive precedence clauses: 3 more (rows 4–6). The council's threshold (≥3 by 2026-10-04) is met on the strict count alone.
- **Every one of the six was resolved at authoring time, in the rule text, by a human**: an explicit `overrides` / `supersedes within scope` / `this file wins` sentence, or a rewrite. **None was resolved at runtime by an engine evaluating precedence.** Two of the three hard collisions were between a project rule and a vendor/harness default, not between two of the project's own levels.

## Decision that follows (user delegated: "choose what is best long-term and correct")

Precedence exists and is needed, but its correct form is **compile-time, not runtime**:

1. Every law whose `scope` overlaps another law's must declare the relationship in frontmatter (`overrides: [law-id]`, `supersedes_in_scope: [law-id]`, or `layers_on: [law-id]`), and the compiler **fails closed on an undeclared overlap**. This turns the six sentences above from prose into checked data and catches the next collision before it is shipped. It is Cedar's forbid-overrides-permit idea applied where these conflicts actually live: at authoring.
2. The L0–L6 ladder remains the ordering the compiler uses to reject an illegal declaration (a lower level may tighten a higher one, never loosen it) and to order concatenated prose. It is a validator over declarations, not an interpreter of conflicts at decision time.
3. **No runtime precedence resolver is built.** Enforcers still compose by conjunction at run time; where two enforcers would disagree, the compiler has already refused to emit them. This is Socrates' checker-package insight with the ladder kept as legislation over the checkers.
4. Harness and vendor defaults are recorded as an explicit level between L0 (safety) and L1 (constitution) for safety-class instructions, and **below L4** for stylistic defaults such as commit trailers; row 1 is the precedent. A law that overrides a vendor default must say so in `overrides:`, exactly as `git-commits.md` already does in prose.

This closes council Kill Criterion 1 with a narrower build than v1 proposed: schema + declaration lint instead of schema + resolver.
