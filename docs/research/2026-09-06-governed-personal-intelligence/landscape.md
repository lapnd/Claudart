# Landscape of Existing Technology — evaluations and capability matrix

Companion to [`README.md`](README.md). Compiled 2026-09-06 from four parallel web sweeps (agent-memory systems; versioned-knowledge and local-first substrates; policy engines and agent rule-enforcement mechanisms; terminology and academic framing). Licenses were read from each repository's LICENSE file where the sweep could reach it; entries marked _(unverified)_ were not. **License posture:** the layer is an internal tool, never embedded in or distributed with a product, so copyleft (GPL/AGPL, and BSL/SSPL for local use) is recorded for information only and does not lower a verdict (README §1.4). Star counts are given only as a weak activity signal and never as a reason to recommend.

**Reading guide:** the verdict column answers one question — _which part of the governed-intelligence problem does this solve, and what can it structurally not do?_ The problem's requirement ids (R1–R9) are defined in the README §1.2.

**Analysis (A).**

- _Commodity:_ fact storage with vector retrieval; local self-hosting under permissive licenses; MCP exposure; cross-session persistence for one agent; automatic consolidation of transcripts.
- _Uncommon but present:_ bi-temporal validity (Graphiti, Statewave); procedural memory as a first-class type (LangMem, ReMe, MemOS, research cluster); human-readable git-diffable storage (Basic Memory, PLUR, CLAUDE.md); framework-agnostic multi-tool design (mcp-memory-service, PLUR, Statewave).
- _Never solved by any surveyed project:_ authority levels over memories (R1); a proposed → approved → binding state machine (R2); evidence-linked rules that get flagged when their evidence changes (R3); structural "know which rules apply before spending a token" retrieval beyond CLAUDART's own trigger-digest convention (R6).
- _Compose with:_ PLUR (substrate shape and cross-tool distribution), Graphiti (validity-interval semantics if a graph is ever justified), Statewave (the compiled-bundle idea, not the Postgres dependency).
- _Traps:_ Zep's cloud-only drift; ecosystem coupling (LangMem, ReMe, Semantic Kernel); immaturity of the two best-fit entrants (PLUR, Statewave); "governance" in vendor marketing usually means access control and retention, not norm promotion.

**Analysis (B).**

1. _Is git + Markdown sufficient for constitution / laws / lessons with review and history?_ Mostly yes, with three additions that cost only a validator script: a frontmatter schema (JSON Schema or CUE) carrying id, status, scope, validity and provenance; a folded index rebuilt on commit so agents load one small file; stable IDs so `superseded_by` never breaks on rename. What git genuinely lacks: semantic merge, query, enforced bitemporal consistency, native cross-repo inheritance.
2. _Best substrate for hierarchical inheritance and override:_ config-layering semantics (CUE strongest: a narrower scope may add or constrain, and a silent contradiction of a higher scope is a type error; Kustomize overlays weaker), then OPA bundles (built for distributing hierarchical policy to many enforcement points, but Rego-shaped), then git submodule/subtree (cheapest, what CLAUDART effectively does, but an override silently shadows the parent). Recommendation at this scale: submodule/subtree or a pinned-clone install now, CUE-style compile-time checks only when silent overrides start biting.
3. _When does a versioned DB beat git files?_ Only when a concrete pain appears: cross-fact query, false textual conflicts on structured fields under concurrent agent edits, enforced bitemporal consistency, or statement-level provenance. Dolt is the smallest step down that ladder.
4. _Local-first sync for one person:_ git itself, to a bare remote; jj as the local front-end for unattended commits; Syncthing only for real-time working-copy needs; CouchDB only if files stop sufficing. Skip CRDT engines and app-sync services.

### C2. Governance processes worth copying

Rust RFC (proposal → final comment period → merge; stabilization report with ecosystem evidence), Python PEP (Draft → Accepted → Final → **Superseded**), Kubernetes KEP (`provisional → implementable → implemented → deprecated`; the enhancements repo _is_ the audit trail). Common shape: a written proposal artifact; named owners and reviewers; a machine-checkable terminal "accepted" state; deprecation points forward to a successor and never deletes history.

AI-side artifacts: Anthropic's constitution (republished 2026-01, reason-based, four-tier priority safety > ethics > compliance > helpfulness); OpenAI Model Spec (platform > developer > user > guideline, with a harm ceiling above all levels); NIST AI RMF (auditable evidence, not adjectives).

Cross-agent distribution: **AGENTS.md** is now stewarded by the Agentic AI Foundation under the Linux Foundation (formed 2025-12), read natively by 30+ tools across 60,000+ repositories; **Claude Code does not read it natively** (only via `@import` or symlink). **Ruler** (`.ruler/` canonical source → every agent's native format, including skills and per-tool subagents) and **rulesync** (`.rulesync/` → 20+ tools, plus tool-to-tool convert) are the two real "compile once" tools; several near-duplicate forks exist and none has won. **None emits the deterministic layer** (hooks, permissions, policy bundles, lint packs), none encodes tiered precedence, none runs a static conflict check, none produces a compliance audit artifact.

### C4. Protocols

MCP resources are the right primitive for exposing versioned, URI-addressed rule documents; no adopted "policy server" was found (a buildable gap). MCP **roots are deprecated** as of spec 2026-07-28; do not build scoping on them. A2A (Linux Foundation, AgentCard discovery) is the agent-to-agent protocol. A 2026 governance-gap analysis (arXiv:2606.31498) finds that MCP, A2A and ACP cannot natively express authority hierarchy, delegation, rule versioning or audit trails: cross-agent governance must be built above the protocols.

**Analysis (C).** Recommended precedence: forbid-overrides-permit with default deny for the _enforceable_ layer (Cedar's proven semantics, generalizing Claude Code's most-restrictive-wins exception into the default for anything tagged law); plain concatenation for the _advisory_ layer, with a lint over the compiled prose flagging direct contradictions. Fully deterministic today: structural code patterns (ast-grep), authorization decisions over structured input (Cedar/OPA), per-tool-call blocks (hooks, deny lists), path and command restrictions, and the whole rule lifecycle state (git + status field). Necessarily LLM-interpreted: whether prose judgement guidance was followed, ambiguous conflicts between advisory rules, and whether a novel situation is covered by any rule at all. Traps: the young, fragmented sync-tool space (keep the canonical source in your own files); vendor-hosted policy editors; assuming any protocol supplies governance semantics.

**Naming verdict.** No single existing term covers both halves. "Governed agent memory" names the mechanics half and is already in the literature; "constitutional memory architecture" names the normative half. For this project the report recommends **Governed Personal Intelligence** as the working name, with the precise description _a versioned, evidence-gated personal constitution executed as governed agent memory_. Ostrom's rule levels are the formal grounding; the nation-state remains a teaching device. The user's refinement (an enabling state that is self-learning and self-evolving) returned no prior hits in the sweep and is treated as an original synthesis, with the "developmental state" (Chalmers Johnson) and "state-reinforced self-governance" literatures as vocabulary sources.

**Unverified in this sweep:** full text of the "Always-On Agents" survey (arXiv:2606.30306); whether "Governed Memory" describes any human-gated amendment mechanism beyond its abstract; the causal story of why NorMAS tooling stalled.
