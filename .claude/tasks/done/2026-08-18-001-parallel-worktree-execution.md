# Parallel Worktree Execution for Disjoint Tasks

## Purpose

> "update claudart flow so that when doing the work it can detect and do the best for maximaize paralles. For example, if thre is a plan/roadmap that has multiple tasks and they are disjosted, they can work in paraleles. Cloudart alway need evaluate and has good plan. In case of coding, to avoid conflcit, need multiple work tree, and when complete the job, need merge, confirm merrged and pushed, then delete worktree"

After this change, any CLAUDART executor (`/spec-run` over a ROADMAP, or a `/plan` task file with independent coding steps) explicitly evaluates whether pending work is disjoint before choosing serial vs. parallel execution, and — when it fans out real coding work in parallel — follows one documented, safe worktree lifecycle: spawn in isolated worktrees, integrate one branch at a time with re-verification, confirm the merge actually landed, push only when already authorized (never a new auto-push grant), and only then delete the worktree. A user can see this working by reading the updated `agent-delegation.md` Worktree Lifecycle section and by observing a `/spec-run` session on a roadmap with an explicit parallel wave: it fans out isolated agents, merges + verifies each one individually, and never deletes a worktree that still holds unmerged work.
